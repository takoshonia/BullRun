# English AI explanations and validation

## Behavior

Every audit first commits a full deterministic report. If AI is configured and the audit contains failures or blockers, a persisted background job generates professional English analysis of distinct actionable groups from that saved snapshot, then saves a new immutable full report version. Passing and review-only audits use a concise deterministic summary and make no AI request. Audit completion and bank requests never wait for the AI provider. Older audits are not automatically sent to AI or charged retrospectively. Use completed audit → **Report version history → Prepare report analysis** for an existing report.

The new version contains all original findings, verdicts, expected/observed evidence, measurements and limits, plus a deterministic outcome summary, prioritised next decisions, grouped passing results, separate draft-rule decisions and explicit coverage gaps. Only failures and blockers receive AI summaries, practical impacts and advisory next steps. The AI cannot change stored audit results. Provenance records the source report ID and snapshot hash, input hash, model, prompt version and generation time. Old report bytes remain unchanged.

The API uses provider-specific structured JSON output with the same application validation. The OpenAI adapter uses Responses and `store:false`; Gemini, Claude and Grok use their own APIs. Only selected redacted finding text is sent, without raw response bodies, account datasets, connection names, tenant identifiers or credentials. Provider requests have one total 45-second deadline, per-connection failover, batches of eight findings, an input limit of 150 findings / 180 KB, and a bounded response size. Reports exceeding these limits retain the full template. Provider-controlled endpoints and models cannot be supplied through the browser.

Validation checks exact finding references, verdicts, expected and observed values, complete ordered coverage, structure, text lengths, English text, unsupported numerical claims, HTML/URLs, known secret patterns and common contradictory assurance claims. These checks do not prove semantic correctness: AI text remains explicitly advisory and requires human review. Source standards and metrics remain in the deterministic report, rather than being generated by AI.

Missing configuration, invalid credentials, rate/quota limits, timeout, provider refusal, incomplete responses and invalid text produce a clearly labelled English template. Failure details expose reason categories, never provider error bodies or secrets. A fallback is a usable report, not an audit failure. After fixing configuration, generate explanations from the latest report version to retry.

Jobs persist in SQLite, deduplicate requests by source report/model/prompt version, and run one at a time. Expired interrupted jobs recover with at most three claims; the saved report request ID also prevents duplicate versions if a process stops between saving a version and updating its job. A tenant can queue at most ten jobs. Operator and the owning bank can request generation; authorized reviewers can read results but cannot initiate paid work. CSRF and existing tenant/diagnostic restrictions apply.

## Live server configuration

Run the installed helper in the DigitalOcean **Web Console** for `geobridge-backend` (`68.183.218.89`), logged in as root:

```sh
python3 /root/configure-geobridge-ai.py
```

Choose **1 Add/update connection**, enter its name, provider, exact model ID and quota group, then paste its API key at the hidden prompt. Repeat for other providers or keys. See [provider pool setup](ai-provider-pool.md) for priority and failover details. The helper writes private `0600` key files and pool metadata owned by the container's Node user in the existing persistent Docker data volume:

- Pool metadata: `/app/data/ai/providers.json`
- Per-connection key: `/app/data/ai/<connection-name>.key`

The Docker image configures `GEOBRIDGE_AI_POOL_FILE` to this pool path; legacy OpenAI key/model files remain supported when no pool file exists. Files are read at runtime, so no container rebuild or restart is required. Refresh the website after configuration. A fresh audit automatically receives AI explanations; for an existing audit use its version history. Actionable groups with successful AI output are labelled **AI-assisted analysis · advisory**. A report with no failures or blockers needs no AI commentary. A labelled fallback reason identifies configuration or validation failures.

Do not enter API keys into the website, GitHub, Vercel frontend settings, or chat. The backend performs the provider calls. Rotate or disable by rerunning the helper or clearing the private key file. Normal database-volume backups also contain these files and must remain private.

## Local configuration

In the repository-root `.env` (ignored by Git), set:

```dotenv
GEOBRIDGE_AI_KEY=your_private_api_key
GEOBRIDGE_AI_MODEL=your_api_model_id
```

Start with `Start-GeoBridge.ps1`, which loads `.env`, or Node 24 `node --env-file=.env src/server.mjs`. Direct environment values take priority over optional private files. Changing process environment values requires restarting the local server; changing configured secret files does not.

API: `POST /api/reports/:id/explanation` returns HTTP 202 and a job; `GET /api/report-explanations/:jobId` returns status and the resulting saved report ID. GET requests never trigger AI calls.

## Verification

Tests simulate provider success and failures, validate REST/schema/privacy settings, reject changed evidence and unsupported claims, preserve source facts despite mutable run changes, verify fallback versions and retry deduplication, recover interrupted jobs, and test HTTP role/CSRF boundaries. A genuine paid provider request still needs your API key and model access.

Official API references: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Responses](https://developers.openai.com/api/reference/resources/responses/methods/create).
