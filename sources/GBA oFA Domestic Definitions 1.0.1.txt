დოკუმენტის შესახებ
ეს დოკუმენტი არის The Berlin Group openFinance API Framework განხორციელების სახელმძღვანელოთა პაკეტის ნაწილი, რომელიც შექმნილია საქართველოს კანონმდებლობასთან თავსებადი ღია ბანკინგისა და მისი გაფართოების, ღია ფინანსების დანერგვის მიზნით. დოკუმენტის მიზანია, სრულად თავსებადი იყოს შესაბამის ჩარჩოსთან (1) და მხოლოდ აზუსტებს მათ მოთხოვნებს, საქართველოს კანონმდებლობისა და ადგილობრივი კონტექსტის გათვალისწინებით.
დოკუმენტის მიზანია, მოახდინოს საქართველოში ღია ბანკინგის სერვისების მაქსიმალური ჰარმონიზაცია და ამ მიზნით, ის აწესებს ბევრ ისეთ შეზღუდვას, რომელთან დაკავშირებითაც The Berlin Group openFinance API Framework ჩარჩო მეტ არჩევანს იძლევა. 
იმ გასაღები სიტყვების ქართული თარგმანების ინტერპრეტაცია, რომელიც მოცემულია ცხრილი 1-ში ("MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", და "OPTIONAL") უნდა მოხდეს (3) შესაბამისად. ტერმინებს ეს მნიშვნელობა აქვთ მხოლოდ იმ შემთხვევაში, როცა ისინი მსხვილი მხედრული  ან/და ᲛᲗᲐᲕᲠᲣᲚᲘ (მთავრული) შრიფტით არიან გამოყენებული.

ტერმინები და აბრევიატურები
ამ დოკუმენტში გამოყენებულ ყველა ტერმინს, რომელიც განსაზღვრულია „საგადახდო სისტემისა და საგადახდო მომსახურების შესახებ“ საქართველოს კანონში, აქვს ამავე კანონით განსაზღვრული მნიშვნელობა, გარდა იმ შემთხვევებისა როცა ამ თავში ტერმინი სხვაგვარად არის განსაზღვრული. 
დოკუმენტში, შემოკლების მიზნით შესაძლოა გამოყენებული იყოს შემდეგი აბრევიატურები:

ამ დოკუმენტის მიზნებისათვის API კლიენტი შეიძლება იყოს ნებისმიერი მხარე, რომელიც ამსმპ-ის სერვისებს უშუალოდ სწვდება. მათ შორის:
მესამე მხარის პროვაიდერი, რომლის საქმიანობა საქართველოს კანონმდებლობის მიხედვით რეგულირდება

ამ დოკუმენტის მიზნებისათვის აუცილებელია ამსმპ-მა მულტისავალუტო ანგარიშად მიიჩნიოს მომხმარებლის ანგარიშების ნებისმიერი ისეთი ერთობლიობა, რომლებსაც ეს ამსმპ სულ მცირე ერთ შემთხვევაში აერთიანებს და გაერთიანებული ფორმით წარუდგენს მოხმარებელს მის მიერ მომხმარებლისთვის სულ მცირე ერთ არხში (ინტერნეტ-ბანკი, მობილ ბანკი და სხვა). 
საერთო ანგარიშის ფორმით წარდგენის არაამომწურავი სია შემდეგია:
ანგარიშების სიაში საერთო სახით ჩვენება (იმ შემთხვევაში, თუ საუბარია ანარიშების სიაზე და არა, მაგალითად, „ჯამური აქტივების“ და „ჯამური ვალდებულებების“ მსგავს ჯამურ ინფორმაციაზე)
დაჯამებული ნაშთის გამოტანა (იმ შემთხვევაში, თუ საუბარია ანგარიშების კონკრეტულ ჯგუფზე და არა, მაგალითად, „ჯამური აქტივების“ და „ჯამური ვალდებულებების“ მსგავს ჯამურ ინფორმაციაზე)
გაერთიანებული ამონაწერის მიღების შესაძლებლობა
ნებისმიერი ტიპის ოპერაციის გატარებისას გაერთიანებაში შემავალი ანგარიშის ამორჩევა ხდება ავტომატურად, წინასწარ გაწერილი სცენარით (მაგ. პრიორიტეტებით) ან მის გარეშე. აღნიშნული არ ვრცელდება იმ შემთხვევაზე, როდესაც სხვადასხვა ტიპის ოპერაციებზე (მაგ. თანხის გამოტანაზე და თანხის შეტანაზე) ანგარიშების სხვადასხვა სიმრავლეა წინასწარ დადგენილი.
შენიშვნა: მიუხედავად იმისა რომ დამკვიდრებული პრაქტიკით მულტისავალუტო ანგარიშებში შემავალ ანგარიშებს, როგორც წესი, ერთიდაიგივე IBAN გააჩნიათ, ამ თავის მიზნებისათვის IBAN-ების იგივეობა ავტომატურად არ ნიშნავს, რომ ანგარიშები მულტისავალუტო ანგარიშს მიეკუთვნება. მეტიც, ზოგიერთ შემთხვევაში მულტისავალუტო ანგარიშში ერთიანდებიან ისეთი ანგარიშებიც, რომლებსაც IBAN განსხვავებული აქვთ.
ანგარიშის იდენტიფიკაცია IBAN-ით
საგადამხდელო ანგარიშთან მიმართებაში IBAN წარმოადგენს ანგარიშის უმთავრეს იდენტიფიკატორს და ამ ტიპის ანგარიშის შემთხვევაში მისი მხარდაჭერა აუცილებელია ყველა იმ შემთხვევაში, როდესაც გამოიყენება Account Reference[n], Account Details და Account Report  (4)-ის შესაბამისად.

ანგარიშის იდენტიფიკაცია pan და maskedPan საშუალებით
შესაძლოა ამსმპ-მა მხარი დაუჭიროს ანგარიშის იდენტიფიკაციას pan-ის მეშვეობით, როდესაც აღნიშნული მნიშვნელობა API კლიენტისგან გადმოეცემა.
აუცილებელია ამსმპ-მა მხარი დაუჭიროს ანგარიშების იდენტიფიკაციას maskedPan-ის მეშვეობით. მხარდაჭერის წესები განისაზღვრება კონკრეტული სერვისების ჭრილში (მაგ. (6), (7), (8) -ის შესაბამისად).
ამსმპ-მა არავითარ შემთხვევაში არ უნდა დააბრუნოს pan ატრიბუტი მის მიერ დაბრუნებულ მნიშვნელობასთან ერთად. მათ შორის, იმ შემთხვევაშიც კი, როდესაც ამსმპ-მა API კლიენტისგან მიიღო pan მნიშვნელობა (თუ ამსმპ აღნიშნულ შესაძლებლობას იძლევა), აუცილებელია, მან მოახდინოს მიღებული pan მნიშვნელობის შენიღბვა და API კლიენტთან შემდგომი კომუნიკაციისთვის ის გამოიყენოს.
თუ ამსმპ ჩათვლის, რომ API კლიენტისგან მიღებული ბარათის ნომერი არასაკმარისადაა შენიღბული (მაგ. არ შეესაბამება PCI DSS მოთხოვნებს ან/და საუკეთესო პრაქტიკებს), შესაძლოა მან იმავე ანგარიშის შესახებ ინფორმაციის უკან დაბრუნების პროცეში უფრო მკაცრი შენიღბვა, ანუ დამატებითი ციფრების ჩაანაცვლოს ‘*’ (ვარსკვლავი) სიმბოლოებით და API კლიენტთან შემდგომი კომუნიკაციისთვის ის გამოიყენოს.
აუცილებელია ამსმპ-მა ბარათის ნომრები შეინიღბოს PCI DSS და სხვა დაკავშირებული მოთხოვნების შესაბამისად, თუმცა ამსმპ-მა არავითარ შემთხვევაში არ უნდა გამოიყენოს იმაზე უფრო მკაცრი შენიღბვა, ვიდრე ამას საკუთარ ონლაინ არხებში (მაგ. ინტერნეტ ან მობილბანკი) იყენებს. 
აუცილებელია შენიღბული მნიშვნელობა უნიკალურად აიდენტიფიცირებდეს კონკრეტულ საბარათე ანგარიშს, სულ მცირე, ამ ანგარიშის მფლობელის ჭრილში.
